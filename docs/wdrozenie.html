Runbook wdrożeniowy · Coolify + n8n + dbt + Metabase

System rozliczeń partnerskich

Kompletna instrukcja uruchomienia: od pustego serwera Coolify do działających dashboardów, które co miesiąc same się aktualizują po odebraniu maila z rozliczeniem. Kroki wykonuj po kolei — każdy kończy się weryfikacją, której wynik warunkuje następny.

Czas wdrożenia: 60–90 min Partner: ZZMP1 Baza: PostgreSQL 16 Stan kodu: zweryfikowany na danych z 2026-07

00

Co budujemy i dlaczego tak

Raz w miesiącu przychodzi mail z jednym załącznikiem Excel. Plik ma pięć arkuszy, dwa oddzielne rozliczenia (kanał główny i Amazon przez MJ), około 300 pozycji sprzedaży i 1100 pozycji magazynowych. System ma to odebrać, sprawdzić, zapisać i pokazać — bez ręcznej pracy i bez ryzyka policzenia tego samego dwa razy.

Cztery decyzje projektowe, które warto znać

Trzy warstwy w bazie

Surowy zrzut arkuszy w JSONB zostaje na zawsze. Jeśli parser kiedyś źle zinterpretuje kolumnę, dane przeliczysz bez proszenia nadawcy o pliki.

Idempotencja na trzech poziomach

SHA-256 pliku jako klucz unikalny, klucz naturalny okresu w bazie, transakcyjne DELETE + INSERT pozycji.

Korekty tworzą rewizje

Poprawiony plik za ten sam miesiąc nie nadpisuje danych — powstaje rewizja 2, stara zostaje w audycie.

Kwoty są sprawdzane

Sześć równań rozliczenia przeliczanych niezależnie po każdym załadowaniu. Różnica powyżej grosza to alert.

Stan weryfikacji

Cały łańcuch — schemat, ładowanie, wszystkie modele i 29 zapytań dashboardowych — został uruchomiony na PostgreSQL 16 na Twoim pliku za 2026-07. Kwoty w bazie zgadzają się z plikiem co do grosza: 60 041,44 zł do zapłaty w kanale głównym, 29 083,15 zł zarobku, 1 485,61 zł w kanale MJ, 269 484,89 zł wartości magazynu. 13 z 13 testów parsera zdanych.

01

Umieść kod w repozytorium GitHub

Rozpakuj dostarczone archiwum i wypchnij je do prywatnego repozytorium. Coolify będzie z niego budował obraz workera przy każdym wdrożeniu.

terminal · lokalnie
unzip rozliczenia-system.zip && cd rozliczenia

git init
git add .
git commit -m "System rozliczeń partnerskich"

# utwórz PRYWATNE repozytorium na GitHub, potem:
git remote add origin git@github.com:TWOJA-NAZWA/rozliczenia.git
git branch -M main
git push -u origin main
Zanim wypchniesz

Upewnij się, że plik .env nie trafia do repozytorium — jest już w .gitignore, ale sprawdź to poleceniem git status. Plik sample/ zawiera prawdziwe dane finansowe, więc repozytorium musi być prywatne. Jeśli wolisz, usuń ten katalog przed pierwszym commitem (testy pominą się same, gdy pliku nie ma).

03

Utwórz zasób w Coolify

  1. W panelu Coolify wybierz projekt (lub utwórz nowy) i kliknij + New Resource.
  2. Wybierz Docker Compose jako typ zasobu.
  3. Wskaż źródło: Private Repository (with GitHub App) i wybierz repozytorium z kroku 01.
  4. Branch: main. Ścieżka do pliku Compose: /docker-compose.yml.
  5. Zapisz — jeszcze nie wdrażaj.

04

Pierwsze uruchomienie i weryfikacja

Kliknij Deploy. Pierwsze budowanie trwa 3–5 minut (instalacja dbt i zależności Pythona). Migracje bazy wykonują się automatycznie przy starcie workera — nie trzeba ich uruchamiać ręcznie.

terminal · weryfikacja
# 1. Worker odpowiada i widzi bazę
curl -s https://rozliczenia.twojadomena.pl/healthz
# oczekiwane: {"status":"ok"}

# 2. Schemat został utworzony (w terminalu Coolify, usługa postgres)
psql -U settlements -d settlements -c "\dt core.*"
# oczekiwane: partner, period, channel, settlement, product,
#            sales_line, stock_snapshot, settlement_note

# 3. Panel ręcznego uploadu działa
# otwórz https://rozliczenia.twojadomena.pl/ i zaloguj się (admin + ADMIN_PASSWORD)
Jeśli healthz zwraca 503

Worker wystartował szybciej niż baza. Sprawdź logi usługi postgres i odczekaj minutę — Docker restartuje kontener automatycznie. Jeśli błąd trwa, zwykle oznacza literówkę w POSTGRES_PASSWORD między usługami.

05

Ustaw hasło roli tylko-do-odczytu

Migracja tworzy rolę metabase_ro z hasłem zastępczym. Metabase będzie łączyć się właśnie nią, żeby narzędzie raportowe nie miało prawa zapisu do danych finansowych. Zmień hasło przed podłączeniem.

terminal Coolify · usługa postgres
psql -U settlements -d settlements

ALTER ROLE metabase_ro PASSWORD 'TU_WKLEJ_METABASE_RO_PASSWORD';

# weryfikacja uprawnień — SELECT ma działać, INSERT nie
\c settlements metabase_ro
SELECT count(*) FROM core.settlement;
INSERT INTO core.partner (partner_code) VALUES ('TEST');
# oczekiwane: ERROR: permission denied for table partner

Wczytanie miesięcy historycznych

Trendy miesiąc do miesiąca zaczną działać dopiero przy dwóch okresach w bazie. Jeśli masz starsze pliki, wgraj je hurtowo — dbt przeliczy modele raz, po wszystkich plikach.

terminal Coolify · usługa ingest
# skopiuj pliki do wolumenu archiwum, potem:
python -m app.cli backfill /data/archive/historia/

# podsumowanie stanu systemu
python -m app.cli status
Kolejność nie ma znaczenia

Pliki możesz wgrywać w dowolnej kolejności — okresy są rozpoznawane z zawartości arkusza (a gdy jej brak, z nazwy pliku), a trendy liczone są po dacie okresu, nie po kolejności wczytania.

09

Utrzymanie

Kopie zapasowe

Usługa backup wykonuje pg_dump codziennie o 3:15 do wolumenu backups, z retencją 30 dni. Prawdziwym źródłem prawdy jest jednak wolumen archive z oryginalnymi plikami Excel — z niego odtworzysz całą bazę poleceniem backfill. Oba wolumeny warto synchronizować poza serwer.

terminal · kopia i odtworzenie
# kopia na żądanie
docker compose exec postgres pg_dump -U settlements settlements \
  | gzip > kopia_$(date +%Y%m%d).sql.gz

# odtworzenie
gunzip -c kopia_20260831.sql.gz \
  | docker compose exec -T postgres psql -U settlements -d settlements

Co miesiąc — po nadejściu rozliczenia

  1. Sprawdź mail z powiadomieniem: status processed i zero nieudanych kontroli.
  2. Otwórz dashboard Proces — karta 4.6 pokazuje rozbieżność między arkuszami Raport i Karta. Rosnąca rozbieżność to sygnał do rozmowy z nadawcą.
  3. Przejrzyj dashboard Magazyn, kartę „Do dozamówienia” — kolumna z sugerowanym zamówieniem na 90 dni.

Aktualizacja kodu

Wypchnij zmiany do gałęzi main — Coolify przebuduje worker przy włączonym auto-deploy. Migracje bazy stosują się automatycznie i tylko raz (rejestr w tabeli ops.schema_migration), więc restart kontenera jest bezpieczny.

Gdy nadawca zmieni format pliku

Parser dopasowuje etykiety, nie numery wierszy — wstawienie nowego wiersza nic nie zepsuje. Zmiana nazwy pozycji lub usunięcie arkusza kończy się statusem failed i alertem, a plik zostaje nienaruszony w archiwum. Poprawka to zwykle dopisanie jednego wariantu etykiety w parser.py i ponowne wgranie pliku.

Zasada nadrzędna

Żaden błąd nie niszczy danych. Oryginalne pliki są w archiwum, ładowanie jest transakcyjne (wchodzi całość albo nic), a korekty tworzą rewizje zamiast nadpisywać poprzednie wartości. W najgorszym razie odtwarzasz całą bazę z archiwum poleceniem backfill.

Po wdrożeniu

Od tego momentu proces jest bezobsługowy: mail przychodzi, n8n go wyłapuje, worker sprawdza kwoty i ładuje dane, dbt przelicza modele, Metabase pokazuje aktualny obraz. Ręcznie dotykasz systemu tylko wtedy, gdy przyjdzie alert — albo gdy chcesz wgrać plik wcześniej niż zrobi to skrzynka.

Naturalne rozszerzenia na później: prognoza zapotrzebowania na podstawie kilku miesięcy sprzedaży, automatyczna lista zamówień w formie pliku Excel do wysłania dostawcy, oraz porównanie rentowności między kanałami, gdy dojdzie więcej niż jedno źródło sprzedaży.
